• 先釐清一個核心概念：RuntimeFrame 是「一次狀態轉移訊息」，不是「完整畫面的檔案」。我前面把這兩個層級講在一起，才會顯得奇怪。

  1. 這些格式分別是什麼？

  ### a. raw ta-browser.v3 full snapshot

  現有正式下載檔大致是：

  ptcs-ta-research-export.v1
  └─ state
     └─ ta-browser.v3
        ├─ updateKind = "full"
        ├─ rows
        ├─ timeline
        ├─ series
        ├─ status
        ├─ query
        └─ revisions

  也就是：

  {
    "schema": "ptcs-ta-research-export.v1",
    "exportedAtUtc": "...",
    "documentRevision": 12,
    "dataRevision": 34,
    "state": {
      "wireVersion": "ta-browser.v3",
      "updateKind": "full",
      "rows": [],
      "timeline": [],
      "series": []
    }
  }

  所謂 raw ta-browser.v3 full snapshot，只是把外層 export envelope 拿掉，直接提供裡面的 state：

  {
    "wireVersion": "ta-browser.v3",
    "updateKind": "full",
    "rows": [],
    "timeline": [],
    "series": []
  }

  它不是另一套 trader-facing 格式，而是目前 browser renderer 已在使用的內部、扁平化 DTO。

  我的建議可以再收斂：

  - trader-facing 正式輸入只承認 ptcs-ta-research-export.v1
  - raw ta-browser.v3 full 僅作內部測試／程式串接能力
  - 不需要在使用說明裡要求 trader 認識 ta-browser.v3

  ### b. delta-only 是什麼？

  full 帶有建立完整畫面所需的目前狀態。

  delta 只帶「相對於上一版增加或改變的部分」，概念上像：

  我以 dataRevision=34 為基礎，
  現在新增了第 35～40 根資料，
  並把 freshness 更新為 Live。

  它不會重新攜帶完整的：

  - 所有 rows/traces
  - 全部歷史 K Bar
  - 所有 SMA／DMI／MACD 點
  - 完整 query/default view
  - 先前已存在的狀態

  所以若只有 delta、卻沒有它宣告的 baseDataRevision，無法知道：

  - 這些點應接在哪一段資料後面
  - 原本有哪些 row
  - 哪個 series 對應哪個 trace
  - navigator 的完整 loaded range
  - 缺少的資料是真的沒有，還是存在於前一版

  「拒絕 delta-only」就是：不能拿一個沒有 base state 的增量訊息，假裝它是一份完整 TA 分析檔。

  如果 notebook 裡已經存在相符的 base state，當然可以接收 delta；拒絕的是「單獨載入一份 delta 當作完整新畫面」。

  ### c. 單一 sdui-runtime.v1 RuntimeFrame 的完整邊界

  需要分成兩種完整性：

  1. Message-complete

     單一 RuntimeFrame 可以是完整、合法的一則訊息。

  2. Render-state-complete

     單一 frame 通常不足以還原完整 TA 畫面。

  現有 RuntimeFrame 的 Kind 只能是以下其中一種：

   Kind         負責內容
  ━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   Document     畫面結構、rows、traces、dataRef、default view、allowed actions
  ───────────  ────────────────────────────────────────────────────────────────
   Snapshot     各 dataRef 的完整資料與 freshness
  ───────────  ────────────────────────────────────────────────────────────────
   Patch        相對於既有 snapshot 的增量變更
  ───────────  ────────────────────────────────────────────────────────────────
   Error        錯誤狀態
  ───────────  ────────────────────────────────────────────────────────────────
   Heartbeat    連線／活性資訊

  每個 frame 只有一種 Kind，而且 Kind 必須和 Payload 相符。

  一份可畫出 TA 圖的 render state，最低通常是：

  Document frame
    + Snapshot frame
    → RuntimeReducer
    → RuntimeState
    → Renderer

  更精確的邊界是：

  - Document 已定義 visible rows、traces 與其 dataRef
  - Snapshot 提供這些 dataRef 對應的資料
  - 兩者的 DocumentId／CanvasInstanceId 一致
  - revision／sequence 可以合法合併
  - 至少有能建立 shared time axis 的主要時間序列
  - 指標 warm-up 前的缺值可以合法存在，不代表整份狀態不完整

  因此，「所有指標每一點都有值」不是完整性的必要條件；但「連 row 要讀哪個 dataRef 都不知道」或「只有 dataRef、沒有資料」就不足以還原完整畫面。

  ### d. 為什麼單一 frame 只有 Document 或 Snapshot？

  這是現有型別的設計：

  type RuntimePayload =
      | Document of TaWorkspaceDocument
      | Snapshot of RuntimeSnapshot
      | Patch of RuntimePatch
      | Error of RuntimeError
      | Heartbeat of RuntimeHeartbeat

  一個 DU value 一次只能是其中一個 case。

  Document 類似圖表配置：

  第一列：K Bar + SMA13 + SMA21
  第二列：DMI7 + ADX7
  第三列：MACD 34/89/144
  共用時間軸、預設顯示最後 160 根

  它不保存 2000 根 OHLCV 與指標數值。

  Snapshot 類似資料表：

  series.es.ohlcv = [...]
  series.sma13    = [...]
  series.dmi7     = [...]
  series.macd     = [...]

  但它本身不負責告訴 renderer：

  - 哪些 series 要放同一列

     29 +

     32 +| 輸入 | 用途 | 時序語意 |

     46 +- 指標參數與 presentation metadata。

     48 +實際的 `QuoteSlot<'T>`、`MarketDataSlot<'T>`、projector closure、credential 與 provider client 只存在 kernel process。它們透過 JSON 中的 stable slot

     51 +
     52 +TA 與可顯示的計算結果在 kernel 端以 `MathNet.Symbolics.FloatingPoint` 表示；每個值必須帶 `EventTimeUtc`，才能讓所有 row 共用同一條時間軸。

     57 +
     58 +不另造 candle/line DTO。projector 用欄位 map 表示一筆 time-keyed presentation row：
     59 +
     60 +```fsharp
     61 +type SduiTimeRow =
     62 +    { EventTimeUtc: DateTimeOffset
     63 +      ReceivedTimeUtc: DateTimeOffset option
     64 +      Fields: Map<string, FloatingPoint> }
     65 +
     66 +type SduiSeriesProjection =
     67 +    { DataRef: string
     68 +      Rows: SduiTimeRow array }
     69 +```
     70 +
     71 +標準欄位名稱固定為：
     72 +
     73 +| 系列 | 欄位 |
     74 +| --- | --- |
     75 +| scalar/line/histogram | `v` |
     76 +| candlestick/volume | `o`, `h`, `l`, `c`, `v` |
     77 +
     78 +wire projector 另外加入 `t`；trader projector 不應自行重複產生不同格式的時間字串。
     79 +
     80 +### 2.4 Opaque typed slot binding
     81 +
     82 +`QuoteSlotBinding`／`MarketDataSlotBinding` 的表示法由 `.fsi` 隱藏。generic factory 捕捉 typed slot 與 projector：
     83 +
     84 +```fsharp
     85 +QuoteSlot<'T>
     86 +  + (QuoteStep<'T> -> Async<Result<SduiProjectionBatch, Diagnostic>>)
     87 +  -> QuoteSlotBinding
     88 +
     89 +MarketDataSlot<'T>
     90 +  + (MarketDataRange<'T> -> Async<Result<SduiProjectionBatch, Diagnostic>>)
     91 +  -> MarketDataSlotBinding
     92 +```
     93 +
     94 +概念實作：
     95 +
     96 +```fsharp
     97 +let commit step = async {
     98 +    let! projected = project step
     99 +    match projected with
    100 +    | Error diagnostic -> return Error diagnostic
    101 +    | Ok batch -> return! sink batch
    102 +}
    103 +
    104 +slot.RunLive commit cancellationToken
    105 +```
    106 +
    107 +如此 runtime 不需 reflection，也不把 `'T` 改成 `obj` 或強迫 slot payload 是 `FloatingPoint`。實際第一個 adapter 使用 `CompletedMarketBar`；未提供 pro
         jector 的 payload 不會被自動接受。
    108 +
    109 +### 2.5 Ownership
    110 +
    111 +binding 建立時必須明示：
    112 +
    113 +```fsharp
    114 +type SduiSlotOwnership =
    115 +    | Borrowed
    116 +    | DisposeWithKernel
    117 +```
    118 +
    119 +- `Borrowed`：runtime release binding 時不呼叫 slot `Dispose`。
    120 +- `DisposeWithKernel`：kernel runtime shutdown 時呼叫一次 slot `Dispose`。
    121 +
    122 +這個選項只處理 resource ownership，不代表 stateful QuoteSlot 可以 multi-subscriber。
    123 +
    124 +## 3. SDUI JSON v1 shape

    152 +## 4. Completed 1K 與 TA pipeline
    153 +
    154 +首個 runtime adapter 的輸入固定為 final `CompletedMarketBar`：
    155 +
    156 +1. 驗證 UTC、`[StartUtc, EndUtcExclusive)`、OHLCV、publication sequence 與 source epoch。
    157 +2. 以現有 `CompletedMarketBarAggregation`／`LiveDerivedBarGraph` 形成 completed 1/5/30/60K。
    158 +3. SMA 使用 `IncrementalSmaState`。
    159 +4. DMI／ADX 使用 `IncrementalDmiState`。
    160 +5. MACD 依 `IndicatorSeriesSpec.ProviderSlotId` 交給既有 `IndicatorProviderRuntime`，或使用已明確選定的現有 provider path。
    161 +6. 將每個 completed bar/indicator 轉成 `SduiTimeRow`。
    162 +
    163 +`IndicatorProviderRuntime` 目前不是所有 TA 的共同容器：MACD 有 provider slot contract；DMI／ADX 與 SMA 使用各自既有 backend API。不得為了讓圖表看起來
         一致而新增假的 indicator source slot。
    164 +
    165 +partial bar、late/out-of-order 或跨 source epoch 資料不在 browser 修補；adapter 依既有 TradeCore validation 回傳 diagnostic。
    166 +
    167 +## 5. FloatingPoint 到 RuntimeFrame
    168 +
    169 +`ISduiRuntimeProjection` 的實作必須：
    170 +
    171 +1. 驗證 `DataRef` 已被 document 使用且已由 binding 宣告。
    172 +2. 將 `EventTimeUtc` 正規化為 UTC 並以 `O` 格式輸出為 `t`。
    173 +3. 只接受 row kind 需要的欄位。
    174 +4. 將可安全表示的 scalar `FloatingPoint` 轉為有限 `SduiValue.Number`／`Text`。
    175 +5. 對 `Undef` 省略欄位或 point；對 NaN、Infinity 與不支援 case 回傳 diagnostic。
    176 +6. snapshot 使用 `RuntimeSnapshot.Data`；incremental update 使用 `PatchOperation.UpsertSeriesPoints(dataRef, "t", rows)`。
    177 +
    178 +frame 順序固定：
    179 +
    180 +```text
    181 +Document(revision D)
    182 +→ Snapshot(data revision N)
    183 +→ Patch(N+1...) / Error / Heartbeat

    186 +browser 要求 resync 時重新發 Document + full Snapshot。revision 與 `TransportSequence` 沿用 Dynamic Contracts，不新增第二套編號。
